4. 多排課模式

項目原本修訂後
新增排程三層模型只有四種排課型態，沒有與營業時間、老師可用性的層級關係營業時間 → 老師可用性 → 課程排課，一層管一件事、由粗到細。學員要約到一個時段，得同時過三關：
  • 店有開——落在營業時間內、不在休息時段。排課超出營業時間：警示但允許（特殊活動可破例）
  • 老師有空——老師該時段可上課；排課撞到老師不可用時段：擋下
  • 真的有開課——該時段有排出場次且名額未滿；同老師／同場地同時段互撞：擋下
少過一關，該時段就不出現在前台
修正時區規則「前台依學員當地時區顯示」——與預約流程的租戶時區規則矛盾統一為：
  • 前台預設租戶時區＋時區名標示
  • 跨國線上課「加註」學員當地時間
  • 預約成立與計算一律以場地時區為準
擴充與課程／營業時間銜接場次時長／名額來源未定義；循環假日只有「可指定跳過日期」
  • 場次時長與名額預設取自課程建立的四欄位，可逐場覆寫
  • 循環排課自動跳過特別日公休
  • 「加入行事曆」分工釐清：單堂歸預約流程、整份課表訂閱為選配

2. 租戶自助設定（本輪最大幅擴充）

項目原本修訂後
擴充課程品項（1.4.2）列了名稱／場地／分類／方案等設定項，無建立流程、無時長人數費用欄位
  • 建立課程的表單只要四個欄位：名稱／時間長度／人數／費用（TWD），填完即可上架
  • 填的「費用」會在背後自動建立一個「單堂固定價」方案並綁定課程；課程資料表不設價格欄位，價格只存在方案上——改費用＝改那個方案的價格
  • 「人數」是每場次的容量上限（額滿判定用），與方案「人數階梯」的計價人數無關
  • 上架／下架做成開關（switch），點了立即生效、不走發佈
  • 刪除做成垃圾桶按鈕：二次確認；有未來場次或未結訂單就擋下；刪除為軟刪除（歷史訂單仍查得到課名）
新增課程｜方案呈現未定義
  • 「課程品項」與「方案」做在同一頁、用 tab 切換
  • 課程編輯面板內嵌方案區塊：可勾選既有方案、也可就地快速建一個單堂價
  • 方案清單每筆顯示「N 個課程使用中」——被綁定中的方案不可刪，要先解綁
新增營業時間與休息時間（1.4.7）沒有營業時間概念（原系統時段寫死）
  • 每週一張基準表：每天一列（開關＝營業／公休）＋起訖時間，可「複製到其他天」
  • 每天可加多段休息時段（如午休 12:00–13:00），須落在營業區間內
  • 特別日（國定假日、臨時公休）逐日覆寫，優先於每週基準
  • 可約時段的計算公式：營業區間 − 休息區間
  • 排課排到營業時間外：跳警示但放行（特殊活動可破例）
  • 前台首頁的營業時間表要把休息時段顯示出來
新增時段顯示與預約時間窗未定義
  • 開課前 X 小時停止線上預約（預設 1 小時）——到點後該場次前台不再顯示可約
  • 只開放未來 N 天內的場次供預約（預設 60 天）——超過的顯示「尚未開放」
  • 時間一律以 24 小時制顯示
新增老師資料（1.4.8）沒有老師資料設定規格
  • 建老師只要填名稱；介紹、照片都選填
  • 沒照片時前台自動以「名稱首字＋色塊」當頭像，版面不留空
  • 老師可綁定「能教哪些課程」，前台選老師步驟據此過濾
  • 上下架開關＋垃圾桶刪除，護欄與課程相同（有未來場次擋刪、可先把場次改派給別的老師、刪除為軟刪除）
  • 老師檔案與登入帳號是兩件事分開存：老師不一定有後台帳號
修正草稿／發佈適用範圍「設定要發佈才生效」與上下架「即點即生效」矛盾
  • 後台操作分兩類，生效方式不同：
  • 設定類（主題、政策、預約流程、報名欄位、營業時間、信件證書範本）：存草稿、按「發佈」才對前台生效，可還原前一版
  • 日常營運類（課程／老師上下架、排序、排課調課）：點了就生效，不走草稿發佈
擴充護欄與變更影響刪除保護只涵蓋場地／課程
  • 刪除前的檢查範圍加上兩種對象：老師、被課程綁定中的方案
  • 縮短營業時間或新增休息時段：已成立的預約與場次照常，只影響之後產生的新時段；若與既有未來排課衝突，列出警示清單給租戶處理、不自動取消
  • User Stories 8 → 13 條、驗收條件同步補齊
